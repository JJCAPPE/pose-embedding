\begin{abstract}
\noindent
The literature does not suggest that contextual metric learning has already been applied to noisy pose-sequence retrieval. Instead, it provides strong but mostly separate components: Kulis's contextual similarity objective for image retrieval, public skeleton/motion encoders, one-shot skeleton metric-learning baselines, robust skeleton-recognition work, and motion-language retrieval systems. The most feasible first result is therefore not a new architecture, but a controlled adaptation: use a public NTU skeleton pipeline, expose a normalized sequence embedding, train standard metric-learning baselines and the contextual loss under the same balanced batches, and compare retrieval degradation under synthetic pose corruptions. The recommended first implementation is MotionBERT's NTU120 one-shot embedding path plus the contextual-loss repository; MMAction2/PoseC3D is the stronger second-stage robustness baseline.
\end{abstract}

\section{Project Framing}

Prof. Kulis's research agenda explicitly includes metric learning, content-based search, clustering, online learning, and applications to audio/visual data \citep{kulisProfile}. The proposed project should therefore be framed as a metric-learning and retrieval problem first:
\begin{equation}
\begin{aligned}
\text{pose sequence} &\rightarrow \text{sequence encoder}
\rightarrow \ell_2\text{-normalized embedding} \\
&\rightarrow \text{nearest-neighbor retrieval}
\rightarrow \text{ranking metrics under clean/noisy poses}.
\end{aligned}
\end{equation}

The central question is narrow enough to test:
\begin{quote}
Does neighborhood-based contextual similarity preserve pose-sequence retrieval quality better than standard pairwise or contrastive objectives when input skeletons are corrupted?
\end{quote}
The relevant corruptions are joint jitter, missing joints, limb dropout, temporal frame dropout, camera/view perturbations, left-right swaps where anatomically meaningful, and 2D-to-3D lifting or detector confidence noise. Classification accuracy alone is not the target. A classifier can remain strong while its penultimate embedding is poorly ranked for retrieval. The correct evaluation unit is a query/gallery retrieval protocol with Recall@K, mAP, mAP@R, and robustness curves.

The main literature gap is the intersection of three lines of work: contextual metric learning for retrieval \citep{liao2023supervised}; skeleton/motion encoders for action recognition or representation learning \citep{yan2018stgcn,duan2022posec3d,zhu2023motionbert}; and robustness studies for incomplete or noisy skeletons \citep{song2020ragcn,shi2020prgcn}. I found strong adjacent work, but not a paper in the supplied archive or subsequent source checks that combines contextual loss, temporal pose embeddings, retrieval ranking metrics, and a controlled pose-noise benchmark.

\section{Contextual Metric Learning}

\citet{liao2023supervised} propose supervised metric learning for image retrieval via contextual similarity optimization. Standard metric-learning losses operate mainly on pairwise or tuplewise distances; their method additionally asks whether two samples have similar neighborhoods. In the public implementation, embeddings are normalized, a batch-level cosine similarity matrix is formed, top-$k$ neighborhood masks are computed, and a contextual Jaccard-like similarity is matched to the label agreement matrix \citep{contextualRepo}.

The important transfer point is that the loss is mostly encoder-agnostic. For pose sequences, the image CNN can be replaced with a TCN, ST-GCN, PoseC3D, MotionBERT, or a simple GRU/Transformer encoder, while preserving the loss-side contract:
\begin{itemize}
    \item the model returns one fixed-length embedding per sequence;
    \item embeddings are $\ell_2$ normalized so dot products are cosine similarities;
    \item each training batch contains multiple examples per class;
    \item the contextual neighborhood size $k$ is tied to the samples-per-class value $M$;
    \item contextual loss is compared against contrastive, triplet, SupCon, multi-similarity, and classification-derived embeddings.
\end{itemize}

The repository audit surfaced one concrete engineering caveat. The 224-by-224 branch exposes the hybrid loss as \texttt{HybridLoss(..., k=args.IPC, eps=args.eps)}, while the 256-by-256 path hard-codes $k=4$ inside its contextual loss. For this project, the loss should be refactored so $k=M$ is always passed explicitly; otherwise the batch sampler and contextual neighborhood definition can silently diverge.

The strongest prior-art warning is from \citet{musgrave2020metric}: metric-learning gains can disappear under careful controls. A defensible result should therefore report clean and noisy retrieval for every loss on the same data split, backbone, augmentation policy, batch composition, embedding dimension, and evaluator.

The training step is intentionally simple:
\begin{verbatim}
z = normalize(encoder(x))              # one embedding per motion
S = z @ z.T                            # cosine similarity matrix
Y = (labels[:, None] == labels[None])  # label agreement
C = contextual_similarity(S, k=M)      # M = samples per class
L = L_context(C, Y) + lambda * L_contrastive(z, labels)
\end{verbatim}

The evaluator should be separate from the training loss. For each trained model, compute embeddings once for clean query/gallery sequences, then recompute query embeddings under each corruption level while keeping the gallery clean. This measures how retrieval degrades when the observed query pose is noisy, which is the use case motivating the project. A second variant can corrupt both query and gallery to simulate fully noisy pose-estimation archives.

Compute risk is moderate. Skeleton sequences are much cheaper than raw video, and the first result can be run on a subset while debugging. The contextual objective scales with the batch similarity matrix, so memory pressure comes from balanced batch size. If needed, reduce sequence length, use MotionBERT-Lite, mixed precision, or gradient accumulation; do not reduce samples per class below the point where contextual neighborhoods become meaningless.

\section{Conclusion}

The concise conclusion for Prof. Kulis is that the proposed project is feasible and nontrivial if it is scoped correctly. Prior work has solved many pieces: contextual similarity for image retrieval, pose and skeleton encoders, one-shot skeleton metric learning, and robust skeleton action recognition. What remains underexplored is the controlled question of whether contextual neighborhoods improve temporal pose retrieval robustness under pose-estimation noise.

The recommended first deliverable is an NTU skeleton retrieval benchmark built from public code. Start with MotionBERT's one-shot embedding pipeline, preserve its normalized embeddings and balanced sampler, add contextual/hybrid loss from the Kulis repository, and evaluate clean/noisy Recall@K and mAP. If this works, the natural second deliverable is MMAction2 PoseC3D or ST-GCN++ under the same evaluator, followed by SportsPose or FineGYM only after the retrieval pipeline is stable.
